# 子任务与执行方式

当前会话负责任务记录、工具执行、集成和验收。外部模型通过 call_model 获取显式文本上下文并返回产物；宿主负责读取仓库、应用补丁、执行命令和验证实际结果。

先读取本轮已发布策略，按任务场景匹配类别，再查询该类别的实时授权候选及类内优先级。普通偏好可根据真实证据调整并说明原因，明确的必须项严格执行。类别不足、权限或输出条件不足时保留具体缺口。能力、价格、耗时和实际验收证据可用于说明调整依据。

主 Agent 当前运行的模型由宿主决定。能选择的宿主角色和推理档位，以本轮实际支持和有效策略为准。不能切换时如实说明，不为模拟降档创建子智能体。原生子智能体仅在任务获准且有实际工具能力时使用。

任务简单或强依赖现场状态时，可由主 Agent 完成。能独立给出输入、产物及验收方法的子任务可分派，例如给一个候选模型分析日志、给另一个模型按接口提出测试。并行需要任务独立，重叠写入、最终集成和部署按依赖及既有归属执行。

首次分派说明任务、模型、类别、优先级、执行工具和验收人。改变首选或提高投入时给出具体原因。结果未知先核对已有记录；已知未执行时才按新决策重发。调用结果、主 Agent 的验收和真实发布分别记录。私有材料发送遵守使用者本轮授权。

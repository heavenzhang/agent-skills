# AI 摇人

显式调用时读取当前安装版本及本轮所需参考。当前会话的主 Agent 对目标、分工、授权、集成、发布协调和最终验收负责。模型选择以本轮任务需要和当前可用能力为依据。保留用户指定的模型和现有部署归属。

## 决定自己做还是分派

每次用本 Skill 执行任务，先读 [MCP 调用流程](references/mcp-workflow.md)，调用 `get_routing_policy({})` 取得当前 `policy` 和 `boundaries`，然后再决定自己做或分派。即使预计自己就能完成，也按此顺序判断。仅在考虑外部候选时查询模型目录。后续重新分派时复核当前适用规则。用户明确要求离线或禁止联网时遵守该限制，按本轮明确授权处理。

普通分工规则是默认偏好。现场证据表明调整更合适时，由主 Agent 决定，并用一句话指出原安排、调整和具体原因。用户明确写“必须”的要求，按其对象和适用条件严格执行。一个规则同时含“优先”和“必须”时分别解释各条要求。符合“必须由主 Agent 执行”的部分即由主 Agent 执行；要求特定模型或验收证据而条件不足时，说明缺口，保持该部分待处理。规则冲突仅在影响决定时请求澄清，继续不受影响的工作。已有权限、费用上限和服务边界始终生效。

规则读取失败时说明原因，先推进不依赖未知规则、且已获明确授权的工作。只讨论方案或明确禁止模型调用时不产生付费调用。若策略文字包含历史接口术语，保留适用意图，以当前实际发现的工具执行。

写出可观察的完成标准，判断依赖、失败后果、交接开销及实际可用工具。按适用策略决定哪些部分由当前 Agent 执行，哪些能明确给出输入、产出和验证方法后分派。互相独立的部分才并行，重叠写入和最终集成按依赖顺序执行。

## 选择模型与执行人

后台已发布的类别与类内优先级决定场景选模。读取 get_routing_policy 返回的 version、policy、boundaries 和 delegation。由主 Agent 根据任务匹配 delegation.rules，保留所有适用的“必须”项；需要分派时，使用规则引用的 category_id 查询 list_models。按返回的优先级降序选择当前可用模型，同级保持配置顺序。普通偏好可因实际任务证据调整，需说明类别、原首选、实际选择和原因。明确必须的类别或执行人按要求执行，候选不足时保留缺口。无匹配场景由主 Agent 自行完成。旧服务缺少 delegation 时按其 policy 正文判断。

类别和顺序统一从后台读取，Skill 内不保存具体模型排名、固定模型名单或默认梯队。不同模型之间按类别优先级选择，选定模型后的渠道优先级和权重由 New API 执行。读取策略与查询候选的版本不一致时，先重新读取；调用时按当前工具能力附带 category_id、policy_version，发布变化导致拒绝时复核新策略后再决定。

按任务的质量标准、可核实的能力证据、上下文和输出容量、延迟、返工及验收成本挑候选。能力合格且总成本接近时，遵从实时策略中的外部模型偏好。高后果任务可直接选已有相应证据的强模型。模型名称、目录可见、价格和本地标签本身都不足以证明水平。依据不足时说明未知。需要比较宿主与外部能力时读 [执行方式与宿主模型](references/hybrid-routing.md)。

首次分派前以「赛博摇人 派工单」说明任务、模型、选择依据、执行工具、预期产物和验收人。当前会话可用短编号关联任务、返回内容、返工和验收记录。仅在实际发出调用后记录已调用，区分请求模型和网关报告的模型标识。

沿用本任务现有费用授权和硬上限。只向已配置、启用且获授权的模型提供任务所需的私有源码、项目文档及脱敏日志。过滤凭据、会话数据和无关材料。调用前不另设例行预算，授权不足时继续能在范围内完成的工作。

## 收回子任务

一次外部请求提交明确任务、必要上下文、预期交付和验收标准。模型可返回可应用的补丁、测试用例或分析。主 Agent 审阅后，通过实际具备工具权限的宿主应用修改、运行测试和复核真实行为。宿主原生子智能体仅在实际可用并获准时使用。

结果不合格时定位是任务描述、模型输出、集成还是环境造成，并附失败证据。有必要返工时显式发起新的有界请求，携带相关原文、上次产物及反馈。对超时、中断和其他结果未知的请求先核对可取得的记录，避免重复费用和副作用。不要自动重放。

完成后简要列出各子任务、模型与执行者、交付证据和验收结果，包括被拒绝或返工的项。费用按可取得的网关用量或参考估算报告，缺失标记未知。主 Agent 对整体做最终判断。实际发布由项目指定负责人按已有流程执行。
